## 1. 要件定義.md

- 目的：楽天 EC の購買データ（大福帳 TEAM_B_DB.DEVELOPMENT.MART_RAKUTEN_PURCHASES_RFM、1,468,432 行、2023/4/1〜2024/3/31）を題材に、直感と実データのズレを体験するクイズゲーム
- 利用者：楽天市場のユーザー（クイズで遊ぶ人）。お題フリーの課題なので絞り込みは軽くてよい。発表では社員が回答者。仕掛ける側（CRM 担当がクイズでポイント・クーポンを配り、回答ログを見る）は発表の「拡張性」で一言触れる程度
- なぜ AI が要るか：毎日新しいクイズを人手で書けない。AI が実データから出題すれば運用コストがほぼゼロ。正解が SQL なのは、客に間違った正解を出せないから
- 演出（骨組みと固定 10 問の後、14:00 以降か CoCo に入らない人が並行）：お買い物パンダが左下で反応（正解・不正解・連勝でセリフ。AI が数字から 1 行）／連勝でレインボーモード（Day4 の CSS を再利用）／5 問 1 セットのクリア演出（ネプリーグ風）／獲得ポイント表示
- できること：①High & Low（A は B より高い？低い？）②虫食いグラフ（隠した区間の形を 4 つから選ぶ）③答え合わせで数字・グラフ・使った SQL・定義を表示 ④スコアと連勝、みんなが外した問題ランキング ⑤AI が新しい問題を作る（集計表から意外な組を選び、問題文と解説を書く）
- できなくてよいこと：自由文で何でも聞ける／将来予測／複数人の同時対戦（画面は 1 台）
- データ：楽天（大福帳）＋天気（SNOWFLAKE_PUBLIC_DATA_FREE の NOAA 日次、東京）。他の公開データは余裕があれば行を足すだけ
- デッキ：カテゴリ／都道府県／月／優良 vs それ以外／天気（雨の日 vs 晴れの日）
- 成功条件：固定 10 問（人が作る）が全部正しく動く＋AI 生成の問題が 1 問以上動く＋発表用 3 問は 14:30 の凍結時点で確認済み
- 制約：Snowflake 上で完結（Streamlit in Snowflake）／CoCo で開発／ロール INTERNSHIP_MEMBER・WH TEAM_B_WH／既存アプリの上書き（プール満杯対策）／凍結 14:30

## 2. 基本設計.md

- 構成：大福帳 → 集計テーブル 5 本（SQL 班）→ 問題テーブル QZ_QUESTIONS（固定 10 問＋AI 生成）→ Streamlit（画面 1 枚）→ 回答テーブル QZ_ANSWERS
- AI：`SNOWFLAKE.CORTEX.COMPLETE(model, prompt)` を SQL から呼ぶ（朝の確認で通ったモデル）。用途は 2 つ。①出題＝集計表（数十行）を渡して「直感と逆になりそうな組」を JSON で 5 つ返させる ②解説＝正解の数字を渡して 2 行の解説文。**正解の判定はプログラム（値の比較）**。AI の JSON は検証してから INSERT
- CoCo（Cortex Code）はアプリ内では使えない（開発者用の CLI）。アプリ内の AI は COMPLETE
- 画面：左サイドバー＝名前・デッキ・モード・スコア・連勝・ランキング／中央＝問題 → 回答ボタン → 答え合わせ（数字・棒または折れ線・解説）→「使った SQL」「定義」の折りたたみ → 次の問題／下＝「AI に新しい問題を作らせる」ボタン
- 虫食いの作り方：週次（または月次）の系列から連続 k 点（月次 3 点／週次 8 点）を隠す。候補 4 つ＝正解＋他カテゴリの同じ区間 3 つ。**min-max で正規化して形だけ比べる**（スケールで答えが割れないように）。答え合わせで元の系列と「他の 3 つは何のカテゴリだったか」を出す
- High & Low の作り方：集計表から 2 行を引き「A の {指標} は B より高い？低い？」。差 3% 未満の組は出さない（引き分け回避）
- 定義（画面に表示）：注文＝顧客 ID×購入日時／平均購入単価＝売上÷注文数／優良顧客＝Day3 の RFM（化粧品購入者で R・F・M 高、2,865 人）／カテゴリ異物（13ページ目・.tsv.gz・3Dプリンター>その他）＝「カテゴリ不明」として比較から除外／Apple Gift Card＝独立扱い（チーム決定に合わせる）
- 天気：NOAA_WEATHER_METRICS_TIMESERIES（東京の観測所、降水量）× 東京都の顧客の日次。雨＝降水 1mm 以上。**平日だけ・中央値・構成比**で比べる（絶対額はセールと週末に飲まれる）

## 3. インタフェース仕様.md

- テーブル（TEAM_B_DB.DEVELOPMENT）

  - QZ_AGG_STATE（state_name, sales, orders, customers, aov）
  - QZ_AGG_MONTH_CAT（purchase_month, category_level_1, sales, orders）
  - QZ_AGG_WEEK_CAT（week_start, category_level_1, sales, orders）
  - QZ_AGG_SEG_CAT（rfm_segment, category_level_1, sales, share）
  - QZ_AGG_WEATHER（date, is_rainy, weekday, category_level_1, sales, orders）※天気班
  - QZ_QUESTIONS（id, deck, qtype 'highlow'/'blank', question_text, item_a, item_b, metric, value_a, value_b, series VARIANT, mask_from, mask_to, choices VARIANT, correct, explanation, sql_text, ai_generated, created_at）
  - QZ_ANSWERS（answered_at, player, question_id, chosen, is_correct）
- 画面の入出力：入力＝名前（任意）・デッキ・モード・回答ボタン／出力＝正誤・数値（3 桁区切り・円）・グラフ・解説（2 行）・SQL・定義
- AI 出題の I/O：入力＝デッキの集計表（最大 50 行を JSON 化）＋指示「直感と逆になりそうな組を 5 つ、{item_a, item_b, metric, question_text, why} の JSON 配列で」／出力の検証＝item が集計表に実在・同一でない・差 3% 以上。合格分だけ INSERT
- 解説の I/O：入力＝問題文・A と B の値・単位／出力＝2 行以内。数字は入力のものだけ使う（新しい数字を作らない）
- エラー時：AI が失敗したら「AI 出題は休憩中」と表示して固定問題を出す（ゲームは止めない）

## 8. Docs の疑問への答え

- CoCo をアプリ内でチャットボットとして使える？ → 使えない。CoCo は開発者用の CLI。アプリ内の AI は `SNOWFLAKE.CORTEX.COMPLETE`（SQL から呼ぶ）。自然言語で SQL を作らせたいなら Cortex Analyst（semantic view）だが今日は範囲外
- 「アプリ内で SQL を書かせる」→ SQL は人が書いたテンプレ 5 本。AI は組と文章を選ぶだけ。「使った SQL」を画面に出せば「AI が選んだ条件を SQL に埋めて実行」と説明できる
- 「数年分の傾向」→ 楽天データは 1 年分（2023/4〜2024/3）。虫食いは週次・月次で作る。複数年は天気（NOAA は 2016〜）だけ
